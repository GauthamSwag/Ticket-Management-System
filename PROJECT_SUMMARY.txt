--------------------------------------------------------------------------------
PHASE 1: AUTHENTICATION, JWT & ROLE-BASED ACCESS CONTROL (RBAC)
--------------------------------------------------------------------------------
- User Model & Schemas:
  * Name, email (unique), password (bcrypt salted hash, 10 rounds).
  * Role-based access control with 3 distinct roles:
    1. 'user': Standard customer/client creating and tracking personal tickets.
    2. 'agent': Technical support personnel handling assigned queues.
    3. 'admin': System administrators managing users, settings, and analytics.
  * Department, phone, active status, timestamps.
  * Password exclusion by default in all API queries (`select: false`).
- JWT Token Authentication:
  * Cryptographically signed tokens using HMAC-SHA256 with 30-day expiry.
  * Extracted via Bearer header in Express middleware.
- Middleware:
  * `protect`: Verifies JWT validity, extracts user identity, rejects invalid tokens.
  * `authorize(...roles)`: Enforces route-level role restrictions.
- User Profile & Admin Directory:
  * Profile view and update endpoints (`GET/PUT /api/auth/profile`).
  * Admin-only user directory endpoint (`GET /api/auth/users`).
- Frontend Authentication System:
  * AuthContext provider with persistent token storage in localStorage.
  * Glassmorphism dark-slate login and registration pages.
  * 1-click demo login buttons for Admin, Agent, and User credentials.
  * Route guards (`ProtectedRoute`) controlling access based on role.

--------------------------------------------------------------------------------
PHASE 2: CORE TICKET MANAGEMENT & LIFECYCLE WORKFLOW
--------------------------------------------------------------------------------
- Sequential Ticket IDs:
  * Implemented atomic sequential ticket ID generator (e.g., TKT-000001, TKT-000002).
  * Unique counter collection ensuring gap-free sequential identification.
- Ticket Data Model:
  * `ticketId`, `title`, `description`, `category`, `priority`, `status`.
  * `createdBy`, `assignedTo`, `resolvedAt`, `closedAt`, `tags`.
  * Category enum: Technical Issue, Account Issue, Billing, Software, Hardware, Network, Other.
  * Priority enum: Low, Medium, High, Critical.
  * Status lifecycle enum: Open -> Assigned -> In Progress -> Resolved -> Closed.
- Lifecycle Transition Rules:
  * Open: Initial state upon ticket creation by any user.
  * Assigned: Set when Admin assigns ticket to a valid Support Agent.
  * In Progress: Agent transitions ticket once investigation begins.
  * Resolved: Agent or Admin marks ticket resolved (stamps `resolvedAt`).
  * Closed: Admin officially closes ticket (stamps `closedAt`).
- Role Scoping & Ownership Security:
  * Users can only view, edit, or delete their own tickets (and only edit while Open).
  * Agents can view and modify tickets specifically assigned to them.
  * Admins have global visibility and reassignment authorization.
  * Direct Object Reference (IDOR) attacks strictly blocked across all routes.
- Frontend Ticket UI:
  * Interactive Ticket Table with responsive sorting, status pills, and priority badges.
  * Create Ticket modal/page with input validation.
  * Detailed Ticket View with dynamic action buttons conditioned on user role.

--------------------------------------------------------------------------------
PHASE 3: COMMENTS, FILE ATTACHMENTS & AUDIT HISTORY
--------------------------------------------------------------------------------
- Ticket Discussion System (Comments):
  * Mongoose Comment model linking ticket, user, message, and timestamps.
  * Real-time comment posting and display.
  * Deletion restricted to comment author or system administrator.
- Secure File Attachment Management:
  * Configured Multer storage engine saving files to `server/uploads/`.
  * Unique file naming with timestamps to prevent collisions.
  * Whitelisted MIME types (PDF, PNG, JPEG, GIF, TXT, DOCX, ZIP).
  * Strict file size limit enforcement (up to 10 MB per file).
  * Secure download endpoint (`GET /api/attachments/:id/download`) validating ticket access.
  * File deletion removing both database record and physical disk file.
- Immutable Activity & Audit Log:
  * `TicketHistory` collection recording every state modification.
  * Actions tracked: TICKET_CREATED, STATUS_CHANGED, PRIORITY_CHANGED, 
    TICKET_ASSIGNED, COMMENT_ADDED, COMMENT_DELETED, ATTACHMENT_ADDED, 
    ATTACHMENT_DELETED, SLA_RESPONSE_BREACHED, SLA_RESOLUTION_BREACHED,
    SLA_CONFIGURATION_UPDATED, AI_CLASSIFICATION_REQUESTED.
  * Records actor ID, timestamp, action type, description, and old/new values.
  * Timeline view rendered in Ticket Details UI.

PHASE 5: SLA MANAGEMENT, MONITORING, EMAIL, AI ADVISOR & HARDENING
--------------------------------------------------------------------------------
- Dynamic SLA Data Model:
  * `SLA` collection in MongoDB storing targets per priority:
    * Low:      24h First Response  / 72h Resolution
    * Medium:   12h First Response  / 48h Resolution
    * High:      4h First Response  / 24h Resolution
    * Critical:  1h First Response  /  8h Resolution
  * Auto-seeded on startup if empty; editable dynamically by Administrators.
- Embedded Ticket SLA Tracking:
  * Fields: `sla.responseDueAt`, `sla.resolutionDueAt`, `sla.responseBreached`,
    `sla.resolutionBreached`, `sla.firstRespondedAt`, and warning notification flags.
  * Deadlines computed dynamically on creation based on active SLA targets.
  * `firstRespondedAt` stamped automatically upon first agent/admin response comment.
- Automated SLA Background Monitor:
  * Implemented using `node-cron` in `server/utils/slaMonitor.js`.
  * Runs every minute inspecting all active, unresolved tickets.
  * Flags Response SLA breaches and Resolution SLA breaches.
  * Detects approaching deadlines (<= 15 minutes remaining) and issues warnings.
  * Deduplication guards prevent duplicate warning or breach alerts.
  * Emits real-time `sla:warning` and `sla:breached` WebSocket events.
  * Writes automated audit records (`SLA_RESPONSE_BREACHED`, `SLA_RESOLUTION_BREACHED`).
- Resilient Email Notification Infrastructure:
  * Nodemailer service in `server/services/emailService.js`.
  * Formatted HTML templates for: Assignment, Status Changes, SLA Warnings, SLA Breaches.
  * Fail-safe operation: When disabled (`EMAIL_NOTIFICATIONS_ENABLED=false`) or SMTP
    is unconfigured, the system safely logs and skips sending without failing the API request.
- User Notification & Email Preferences:
  * Extended User model with `notificationPreferences`:
    `emailEnabled`, `assignmentEmails`, `statusChangeEmails`, `slaEmails`.
  * Dedicated "Notification & Email Preferences" section on `/profile` page.
- AI-Assisted Advisory Ticket Classification:
  * Optional advisory service in `server/services/aiClassificationService.js`.
  * Analyzes ticket title & description to suggest Category, Priority, and Confidence score.
  * Non-destructive: Never overwrites user-selected category or priority values.
  * Heuristic NLP fallback provides intelligent suggestions even when external AI is off.
  * Endpoint: `POST /api/tickets/:id/classify` (accessible to Creator, Assigned Agent, Admin).
  * Logs `AI_CLASSIFICATION_REQUESTED` to immutable audit history.
- Admin SLA Rules Management (`/admin/sla`):
  * Dedicated admin page for viewing and editing response/resolution hours inline.
  * Protected by both frontend role guard and backend `authorize('admin')`.
- Enhanced Admin SLA Analytics Dashboard:
  * `/analytics` tabbed view adding "SLA Compliance & Monitoring".
  * MongoDB aggregations: SLA Overview, Priority Breakdown, Breach Trends, Agent SLA Table.
- Ticket SLA Filtering:
  * Extended `GET /api/tickets` with `slaStatus` filter (`within_sla`, `approaching`, 
    `response_breached`, `resolution_breached`).
- Production Hardening & Error Standardization:
  * Standardized API responses: `{ success: true/false, message: '...' }`.
  * Zero exposure of sensitive fields (password hashes, JWT secrets, SMTP passwords, AI keys).

PHASE 7: SERVER-SIDE SEARCH, FILTERING, SORTING & PAGINATION
--------------------------------------------------------------------------------
- Hardened Backend Query Processing (`GET /api/tickets` in `ticketController.js`):
  * Strict RBAC Scoping Evaluated First:
    - User: Restricted strictly to `createdBy: req.user._id`.
    - Agent: Restricted strictly to `assignedTo: req.user._id`.
    - Admin: Full visibility across all system tickets.
  * Regex Injection & ReDoS Protection:
    - Search input strings are sanitized with `replace(/[.*+?^${}()|[\]\\]/g, '\\$&')`.
    - Multi-field search across `ticketId`, `title`, and `description` (case-insensitive `$regex`).
  * Advanced Multi-Parameter Filtering:
    - Status (`Open`, `Assigned`, `In Progress`, `Resolved`, `Closed`).
    - Priority (`Low`, `Medium`, `High`, `Critical`).
    - Category (`Technical`, `Billing`, `General`, `Feature Request`, `Bug Report`).
    - SLA Status (`within_sla`, `approaching`, `response_breached`, `resolution_breached`).
    - Administrative scoping filters (`assignedTo`, `createdBy`).
    - Date range validation (`fromDate`, `toDate`) returning 400 Bad Request on invalid dates.
  * Sorting Strategy with Safe Fallback:
    - Support for `sort` convenience alias (`newest`, `oldest`, `priority_desc`, `priority_asc`,
      `recently_updated`, `title_asc`, `title_desc`).
    - Safe fallback to `newest` on unknown or missing sort values.
    - Preserved `sortBy` and `sortOrder` for backward compatibility with existing tests.
  * Standardized Pagination Metadata:
    - Slices results via MongoDB `.skip()` and `.limit()`.
    - Returns standardized metadata payload:
      `{ totalItems, totalPages, currentPage, page, limit, hasNextPage, hasPreviousPage }`.
- Frontend Ticket Management Experience (`client/src/pages/Tickets.jsx`):
  * 100% Server-Side Driven: Client never downloads all records to filter in memory.
  * Responsive Filter Control Bar:
    - Debounced Search input (350ms) with one-click clear button.
    - Status, Priority, Category, and Sorting dropdowns.
    - SLA status filter and items-per-page toggle (10, 25, 50).
    - "Clear Filters" button to reset state.
  * Responsive Pagination Footer:
    - Showing X-Y of Z item indicator.
    - Previous and Next buttons with disabled state handlers.
    - Page indicator ("Page X of Y").
  * Real-Time WebSocket Synchronization:
    - Socket.IO ticket events automatically trigger debounced re-fetch of the active query.
